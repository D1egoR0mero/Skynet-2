# User Stories: Skynet Internship Finder — Include/Exclude Keyword Filtering

## US-002 — Filter listings with explicit include and exclude keywords

**Story:** As a student searching for internships, I want to enter the keywords a role must contain and the keywords it must not contain, so that I can remove roles I am uninterested in or unqualified for without scanning the whole result list by hand.

**Acceptance Criteria**

1. Given the full listing set is loaded and both keyword inputs are empty, when the user types `the, walt, disney, company` into Include keywords, then the results recompute as each character is typed with no button press, and only listings whose displayed title and company together contain all four terms survive — for example a listing titled "Software Engineering Intern" at "The Walt Disney Company" remains visible, while a listing at "Walt Disney Company" does not, because it lacks `the`; the matching-results counter reflects the surviving count.
2. Given Include keywords is `the, walt, disney, company`, when a listing's title and company contain `walt`, `disney`, and `company` but not `the`, then that listing is absent from the results and is not included in the matching-results counter, because one missing include term is enough to remove it.
3. Given Include keywords is empty, when the user types `senior, manager` into Exclude keywords, then a listing titled "Senior Software Engineering Intern" at "The Walt Disney Company" and a listing titled "Engineering Manager" at "The Walt Disney Company" are both absent, while "Software Engineering Intern" at "The Walt Disney Company" remains visible and counted, because any single matching exclude term removes a listing.
4. Given Search, Include keywords, Exclude keywords, Location, Opportunity type, Posted since, and the Explore/Saved view are all populated, when the user views the results, then every visible listing satisfies every populated control at once; and given the user is viewing a later results page, when any one control changes, then the results return to page 1 and are re-paginated over the newly filtered set.
5. Given the keyword fields are the only populated controls, when the tester enters each of the following into Include keywords in turn — (a) ` the , walt , disney , company ` with stray spaces, (b) `DISNEY, disney, Disney`, (c) `intern`, (d) `c++`, (e) `.*` — then (a) and (b) return exactly the same listing set and counter value as a single trimmed lowercase occurrence of those terms; (c) keeps a listing whose title contains `internal` as well as one containing `internship`, because matching is literal substring rather than whole-word; (d) matches only listings whose title or company literally contains the characters `c++` and raises no error; and (e) treats the dot and asterisk as literal characters, so a listing matches only if its title or company literally contains `.*`; entering only whitespace or separators applies no restriction from that field.
6. Given Include keywords is a term that appears in no listing title or company, when typing completes, then the results area shows the existing "No matching opportunities. Try clearing your filters." message, the matching-results counter reads 0, and pagination reads "Page 1 of 1"; when the user then activates Clear filters, then both keyword fields and the other search controls are emptied, the full listing set returns with a matching-results counter equal to the total available roles, pagination starts at page 1, and the Explore/Saved view selection is unchanged.

**Priority:** Must-have (MoSCoW) — the README's feature list names "Custom include/exclude keyword filtering" as a headline capability of the product, and the shipped web app does not deliver its stated feature set without it.

**Related requirements:** Refines US-001 — `docs/requirements/US-001-web-funnel-search.md` — by adding explicit include/exclude keyword filtering to the web app's existing search, Location, Opportunity type, Posted-since, saved, and pagination behaviour. Design record: ADR-0002 — `docs/design/ADR-0002-keyword-filter-placement.md`. The implementation is delivered on the `pm2.2-include-exclude-keywords` branch and is not yet merged into `main`.

**Assumptions / dependencies:** The page exposes two labelled fields, "Include keywords" and "Exclude keywords", with helper text stating that title and company must contain every included keyword and none of the excluded keywords. Every listing in the array returned by `/api/listings` exposes `title` and `company`; tags, terms, and location deliberately do not contribute keyword matches. Keyword filtering happens in the browser with no server or API change. The pre-existing search, Location, Opportunity type, Posted-since, and Saved-view controls and their current matching behaviour are unchanged, and the keyword fields combine with them using AND. Clearing filters empties the keyword fields along with the other search controls while preserving the selected Explore/Saved view.
